# Plan for Foxglove WebSocket Protocol Implementation

## Overview
Replace the existing ROS Bridge Suite implementation with Foxglove's WebSocket protocol.

## Steps

1. Create a new Foxglove source provider:
   - Implement a FoxgloveSourceProvider component based on the existing RosBridgeSuiteSourceProvider
   - Replace ROSLIB with @foxglove/ws-protocol client

2. Interface Changes:
   - Define a FoxgloveSourceSettings interface to replace RosBridgeSuiteDataSourceSettings
   - Create a FoxgloveSourceContext

3. Connection and Topic Management:
   - Implement connection to Foxglove WebSocket server
   - Create methods for subscribing to channels/topics
   - Implement topic advertisement and publishing
   - Handle reconnection logic

4. Message Handling:
   - Create message conversion utilities between Foxglove format and unified application format
   - Update or create converters as needed

5. Plugin Integration:
   - Set up the same filter/action hooks as the existing ROS Bridge provider
   - Keep API compatibility to ensure minimal changes to dependent components

6. Topic Discovery:
   - Implement methods to discover available topics from Foxglove server
   - Handle schema/type information

7. Testing:
   - Test basic connectivity
   - Test subscription to topics
   - Test publishing to topics
   - Test schema retrieval

## Key Differences Between RosBridge and Foxglove WebSocket Protocol

1. Connection:
   - RosBridge: Uses WebSocket connection with ROSLIB client
   - Foxglove: Uses WebSocket with Foxglove's client protocol

2. Topic Discovery:
   - RosBridge: Uses ROS services for topic discovery
   - Foxglove: Uses server-advertised channels

3. Subscriptions:
   - RosBridge: Subscribes with ROS topic name and message type
   - Foxglove: Subscribes to channels with encoding information

4. Publishing:
   - RosBridge: Publishes through ROS topics
   - Foxglove: Publishes to channel with specific message format

5. Schemas:
   - RosBridge: Fetches message definitions through ROS services
   - Foxglove: Receives schema information from server when subscribing
